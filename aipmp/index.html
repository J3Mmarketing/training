AI 在專案管理的三種角色

根據 PMI《AI Essentials for Project Professionals》，AI 介入專案管理的方式分三層，任務複雜度越高，人類主導的比重也越大。

自動化 Automating
機器主導
低複雜任務，AI 獨立完成。
例：會議記錄摘要、逐字稿生成
輔助 Assisting
人機協作
中高複雜任務，人機共同完成。
例：風險分析、成本與時程估算
增強 Augmenting
人類主導
高決策任務，AI 提供支援。
例：專案決策、商業案例創建
⚡
核心原則：Garbage in, Garbage out——輸入品質決定輸出品質。提示詞的精準程度，直接影響 AI 產出的可用性。

提示詞框架：CREATE

結構化提示語設計框架，適用於所有 AI 工具指令撰寫。六個維度缺一不可。

C
Character
界定 AI 的專業角色（例：資深系統分析師）
R
Request
明確表達要 AI 完成的任務內容與目標
E
Example
提供參考範例或輸出樣本，降低模糊性
A
Adjustment
定義邊界限制與調整條件（例：排除法）
T
Type
指定輸出格式（例：Markdown、Table、JSON）
E
Evaluation
提供驗證步驟，確保產出符合專業標準

Demo 0 — 製作 Gem 專案管理小幫手

Gem 是 Gemini 的自訂 AI 角色功能，可事先植入角色設定與規則，讓 AI 在每次對話中自動套用。以下為完整提示詞，可直接貼入 Gem 設定介面。

ℹ
操作路徑：Gemini 主頁 → 左側欄「Gems」→「建立新 Gem」→ 貼上以下提示詞 → 儲存並測試。
GEM SYSTEM PROMPT · 可直接複製使用 
Purpose and Goals:

* 擔任使用者的「AI 專案管理幫手」，協助進行專案的時程控管與會議通知管理。
* 根據使用者提供的 WBS（工作分解結構），分析各項任務的優先級、工期與相依性。
* 監控專案進度，主動提醒潛在的延遲風險並提供調整建議。
* 自動化生成專業的會議通知，確保團隊溝通效率。

Behaviors and Rules:

1) WBS 分析與時程規劃：
   a) 請使用者輸入 WBS 內容或上傳相關文件。
   b) 根據 WBS 建立甘特圖邏輯或關鍵路徑分析。
   c) 定期詢問任務完成進度（0%-100%）並更新時程表。

2) 任務提醒與風險控管：
   a) 若任務接近截止日期，發出溫馨提醒。
   b) 若任務已逾期，分析對後續任務的影響，並建議修正方案。

3) 會議通知生成：
   a) 根據專案里程碑或特定需求，生成包含會議主題、時間、
      地點、議程及參與人員的通知草稿。
   b) 確保通知格式簡潔專業，並包含回覆確認連結或截止日期。

4) 交談規則：
   a) 每次對話保持專業且高效的風格，回答不超過 3 個重點段落。
   b) 在提供具體建議後，總是以一個確認問題結尾，
      例如：「您是否需要我為這項延遲重新計算關鍵路徑？」

Overall Tone:
* 使用專業、嚴謹且有條理的語言。
* 展現出高度的組織能力與邏輯思維。
* 讓使用者感到專案處於受控狀態，增加管理信心。
建議上傳的參考資料
  • WBS 表格（Google Sheets 或 Excel）：讓 AI 掌握專案結構與任務關係
  • 專案章程或 SRS 文件：提供背景知識，避免 AI 憑空推測
  • 前次會議記錄：建立對話的延續性脈絡

實作 Demo 流程

DEMO 1 語音檔案 → 自動化會議記錄
工具組合：手機錄音 → Google AI Studio → NotebookLM → Google Tasks
  • 1
    語音紀錄
    會議中以手機錄音或會議軟體（如 Google Meet、Zoom）內建錄製音檔。建議格式：MP3 / M4A，長度不限。
  • 2
    逐字稿生成
    將音檔上傳至 Google AI Studio，使用 Gemini 快速轉錄為文本逐字稿。可加入語言提示提升中文辨識準確率。
  • 3
    NotebookLM 提煉摘要
    將多份逐字稿上傳至 NotebookLM，AI 自動交叉比對，提煉決策摘要、待確認事項與關鍵討論點。
  • 4
    Action Items 分類
    AI 自動分類代辦事項並標記負責人，輸出為結構化清單，格式可指定為 Markdown 或表格。
  • 5
    同步工作行事曆
    一鍵串接 Google Tasks 與日曆提醒，設定截止日前 48 小時自動推播通知。
可用提示詞範例
PROMPT · 逐字稿 → 會議記錄 
你是一位專業的專案會議記錄助理。

以下是本次會議的逐字稿：
[貼上逐字稿內容]

請依照以下格式整理會議記錄：
1. 會議摘要（3 句話以內）
2. 決策事項（條列，含決策人）
3. Action Items（表格格式：任務 / 負責人 / 截止日期）
4. 待確認事項（需後續跟進的問題）

輸出語言：繁體中文，格式：Markdown
DEMO 2 WBS 展開 + 進度回報給 PM
參考文件：HR 系統專案進度報告 PDF · 工具：Gemini + Google Sheets
✦
此 Demo 使用 Gem 專案管理小幫手操作。先上傳 HR 系統 WBS 文件，再依步驟執行。
  • 1
    上傳 WBS 文件
    將專案進度報告 PDF 上傳至 Gem 對話視窗，AI 自動解析任務結構、負責人與時程。
  • 2
    請 AI 分析關鍵路徑
    AI 識別 Finish-to-Start 任務依賴關係，計算 Total Float，標記零緩衝的關鍵節點。
  • 3
    生成 PM 進度回報
    依照目前進度，AI 自動草擬專業進度報告，包含摘要、風險評估與下一步建議。
  • 4
    轉為 Google Sheets
    將優化後的 WBS 時程轉換為 Google 試算表格式，加入任務狀態欄與時程說明欄。
可用提示詞範例
PROMPT · WBS 進度回報 
@Gmail 依照我目前工作進度，回報給 PM

（上傳 WBS 文件後使用）

請依照以下架構整理進度報告：
1. 進度達成摘要（目前整體狀況，100 字以內）
2. 後續關鍵任務（列出下 2 項任務、預計完成日、負責人）
3. 風險管理與分析（目前風險等級、潛在延遲項目）

格式：條列式，語言：繁體中文，語氣：專業正式
PROMPT · 關鍵路徑重新計算 
重新計算關鍵路徑，以確認 [月份] 開發階段的緩衝時間

請提供：
1. 目前關鍵路徑分析（任務鏈與依賴關係）
2. 各階段緩衝時間計算（以工作天為單位）
3. 若 [任務名稱] 延遲 N 天，對後續的影響評估
4. 優化建議（如何創造管理緩衝）
PROMPT · 轉換為 Google Sheets 格式 
改成用 Google Sheet 展開 WBS 檔案日期

請將上述 WBS 時程轉換為 Google 試算表格式，欄位包含：
- 任務編號
- 工作項目
- 負責角色
- 原定開始日 / 原定結束日
- 調整後開始日 / 調整後結束日
- 任務狀態（待開始 / 進行中 / 完成 / 延遲）
- 時程說明（標記與原定日期的差異）

並在最後加入「風險監控重點」備註欄。
DEMO 3 法規 → 系統規格書（Spec）
參考文件：缺勤系統法規檢核邏輯 PDF · 工具：Gemini
▲
此 Demo 展示 AI 進行「邏輯壓力測試」——將法規條文轉換為系統可執行的驗證規則，是 WBS 中「邏輯驗證」環節的核心應用。
  • 1
    上傳法規文件
    將《勞動基準法》相關條文或內部整理的法規 PDF 上傳至 Gemini 對話。
  • 2
    提取檢核邏輯
    AI 依照核心工時管控、休息例假規定、特殊身分限制等面向，結構化輸出排班檢核規則。
  • 3
    生成規格書初稿
    針對百貨服務業等特定情境，AI 結合平日/假日班次設定、大小月彈性配置，產出系統規格書。
  • 4
    進行邊界測試
    針對變形工時（二週、四週、八週）等邊界情境進行邏輯壓力測試，確認規格的完整覆蓋度。
可用提示詞範例
PROMPT · 法規 → 系統排班檢核邏輯 
法規檢核

我要製作出缺勤系統，依照法規列出系統排班檢核邏輯

（上傳勞基法相關文件後使用）

請依照以下架構輸出：
1. 核心工時與加班上限管控（每日 / 每週 / 每月上限）
2. 休息、例假與輪班間隔設定（一例一休規則）
3. 特殊身分排班限制（童工、妊娠/哺乳期女性勞工）
4. 變形工時邏輯（二週 / 四週 / 八週彈性規則）

每條規則請以「條件 → 系統行為」格式說明，
並標註對應的勞基法條文編號。
輸出格式：Markdown 表格
PROMPT · 系統排班規格書（百貨業情境） 
寫出系統排班規格書，以百貨公司服務業為例
平日上班時間：早班 09:30，假日上班時間：10:00
下班時間：平日/假日 22:30，共兩班
系統彈性設定：依照大小月可自行設定早晚班排班人數

請整合以下需求產出規格書：
1. 班次設定規則（早班 / 晚班 / 平假日差異）
2. 起訖時間自動判定邏輯
3. 大小月人力彈性配置機制
4. 四週變形工時合規檢核邏輯
5. 管理員操作說明（如何調整各班別人數上限）

格式：完整規格書，使用 Markdown 標題層級
