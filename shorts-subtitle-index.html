把旁白變成看得懂的字卡：FFmpeg 上字幕實戰

一支 1 分鐘的 AI 教學短影音，字幕做得好不好，決定觀眾是滑走還是看完。這份手冊拆解從語句邊界偵測到燒錄輸出的完整流程，每個環節都附可直接複製的指令，以及當初踩過的坑。

01量素材：先知道自己在剪什麼

所有後續參數都從這一步的數字推導出來。跳過這步，字級、邊界、時間軸全部都是猜的。

ffprobe · 讀規格
# 一次讀出時長、解析度、幀率、音軌聲道
ffprobe -v error -show_entries format=duration,size \
  -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,channels \
  -of default=noprint_wrappers=1 main.mp4

要記下來的四個數字

項目本次實例它決定了什麼
影片尺寸720 × 1280需升到 1080×1920，字幕字級要照 1080 的基準算
幀率30 fpsASS 時間精度到 0.01 秒即可，不必更細
總長62.5 秒扣掉片尾 logo 卡後，實際可用 59.34 秒
音軌單聲道 44.1 kHz與片尾素材規格不同，串接前必須統一
原理

字幕字級不是憑感覺調的。可用寬度 ÷ 每行字數 = 字級上限。以 1080 寬、左右各留 70px 邊界為例，可用寬度 940px；若希望單行最多容納 14 個中文字，字級上限就是 940 ÷ 14 ≈ 67px。本次取 66px。

02抓語句邊界：字幕對齊的地基

這是整份手冊最關鍵、也最常被跳過的一步。字幕之所以「跟不上嘴」，九成問題出在這裡。

為什麼不能直接用語音辨識給的時間軸

ASR 工具輸出的 SRT，斷點是按語意分組的，不是按說話者的呼吸。它會把一整段話併成一個區塊，然後給一個橫跨多句的時間範圍。照套進影片，字幕就會整段停在畫面上，或整段提前消失。

指令

silencedetect · 找停頓
# noise：低於此音量視為靜音　d：至少持續多久才算一次停頓
ffmpeg -i main.mp4 -af "silencedetect=noise=-32dB:d=0.35" -f null - 2>&1 \
  | grep -E "silence_(start|end)"

輸出會長這樣，silence_end 到下一個 silence_start 之間，就是一個完整語句：

輸出範例
silence_start: 2.69351
silence_end:   3.14066  | silence_duration: 0.447143
silence_start: 6.69361
silence_end:   7.22458  | silence_duration: 0.530975

→ 語句 1：0.00 – 2.69　語句 2：3.14 – 6.69　語句 3：7.22 – ...

參數怎麼調

情況調整理由
切出來太碎（一句被切成三段）d=0.5 或更大忽略句中的短換氣
整段沒切開d=0.25TTS 旁白停頓通常較短
有背景音樂noise=-25dB底噪抬高，門檻要跟著抬
驗收方法

拿每一段的字數除以秒數。中文旁白正常落在 4–6 字／秒；TTS 旁白偏慢，約 4–5。任何一段掉到 2 以下或衝到 9 以上，就是那一段對錯了，回頭檢查。這個檢驗只要一分鐘，卻能擋掉九成的字幕錯位。

03切字卡：逐字稿不等於字幕

短影音字幕的本質是「畫面下標題」，不是聽打稿。觀眾是用眼睛掃過去的，不是逐字閱讀。

三條硬規則

  1. 一張字卡對應一個語句邊界。超過 4 秒的長語句，從語意的自然停頓處對半切成兩張。
  2. 單行 10–14 字，最多兩行。超過就換行或改寫，不要縮小字級去塞。
  3. 刪贅字、留關鍵字。旁白說「它會主動幫你把緊急的郵件挑出來」，字卡寫「它會主動挑出緊急郵件」。
✕ 逐字照搬

「甚至在你點開前就根據上下文，擬好回信放進草稿。」
21 字擠成三行，觀眾讀完字卡已經播完了。

✓ 拆成兩張下標題

「甚至在你點開前」
「就依上下文擬好回信／直接放進草稿」
節奏跟著旁白走，關鍵字被標出來。

分段標題另設一套樣式

如果內容是「五大用法」這種列舉結構，把「第一、第二、最後」獨立成整行品牌黃的章節卡，與白色內文字卡區隔。觀眾中途滑進來，一眼就知道現在講到第幾點——這對完播率的幫助比任何轉場特效都大。

時間軸怎麼算

把每個語句邊界的起訖時間，依字數比例分配給該語句底下的字卡。例如語句 14.17 – 18.78（4.61 秒）要放兩張字卡、字數 7 與 13，則切點落在 14.17 + 4.61 × (7/20) ≈ 15.8 秒。

04寫 ASS：為什麼不用 SRT

SRT 只有文字和時間，字體、位置、單字變色一律做不到。要做出品牌一致的字幕，必須用 ASS。

檔案骨架

欄位本次設定作用

行內標籤

標籤用途

\N強制換行
最大的坑：色碼是 BGR，不是 RGB

ASS 的顏色格式為 &HAABBGGRR&，紅藍順序與 CSS 相反，而且前兩碼是透明度（00 為完全不透明）。品牌黃 #F5B800 要寫成 &H00B8F5&。直接把 CSS 色碼貼進去，黃色會變成藍色。

第二個坑：字型名稱要用系統實際註冊的名字

先用 fc-list :lang=zh 查出可用的中文字型，照抄它回報的家族名（例如 Noto Sans CJK TC Black）。名稱打錯不會報錯，libass 會靜默換成預設字型，你要到輸出成品才會發現字型不對。

05燒錄、變速、疊圖

一次 filter 鏈把升尺寸、燒字幕、疊截圖、變速全部做完，避免多次重編造成畫質損失。

最小可用版本

燒錄字幕 · 升至 1080×1920
ffmpeg -i main.mp4 \
  -vf "scale=1080:1920:flags=lanczos,fps=30,setsar=1,ass=sub.ass" \
  -c:v libx264 -preset slow -crf 19 -pix_fmt yuv420p \
  -c:a aac -b:a 192k out.mp4

變速：旁白太滿時的正解

當旁白句間停頓只有 0.4–0.7 秒，全片幾乎沒有空白可剪，硬跳剪會截斷語句。這時應該整體變速，而不是跳剪。atempo 會保留音高，1.4 倍以內聽感自然。

變速後字幕時間要同步換算

所有 ASS 時間軸都必須除以倍率。原片 14.17 秒的字卡，在 1.4 倍加速後要寫成 14.17 ÷ 1.4 = 10.12 秒。作法上，先在原始時間軸算好所有斷點，最後統一除一次，不要邊算邊換算。

變速 ＋ 燒錄 ＋ 疊圖 · 完整 filter 鏈
# -t 放在 -i 之前才是「裁切輸入」；放在後面只會限制輸出長度
ffmpeg -t 59.34 -i main.mp4 \
  -loop 1 -framerate 30 -t 3.45 -i card.png \
  -filter_complex "
    [1:v]format=rgba,
      fade=t=in:st=0:d=0.20:alpha=1,
      fade=t=out:st=3.25:d=0.20:alpha=1,
      tpad=start_duration=22.40:start_mode=add:color=black@0[ov];
    [0:v]setpts=PTS/1.40,scale=1080:1920:flags=lanczos,
      fps=30,setsar=1,ass=sub.ass[base];
    [base][ov]overlay=x=(W-w)/2:y=620-h/2:eof_action=pass[v];
    [0:a]atempo=1.40,
      aformat=sample_fmts=fltp:sample_rates=48000:channel_layouts=stereo[a]
  " \
  -map "[v]" -map "[a]" \
  -c:v libx264 -preset slow -crf 19 -pix_fmt yuv420p \
  -c:a aac -b:a 192k segA.mp4

疊圖的三個要點

  • 用 tpad 做延遲進場。tpad=start_duration=22.40:start_mode=add:color=black@0 會在圖片前面補上透明幀，時間戳才會正確對齊。前面必須先 format=rgba，否則透明通道會被丟掉。
  • 淡入淡出寫在 tpad 之前。此時圖片串流的時間軸還是從 0 起算，fade 的 st 用相對時間即可。
  • 字幕先燒、疊圖後上。filter 鏈的順序決定圖層。把疊圖錨在畫面上半部（本次 y=620-h/2），字幕在下方 300px，兩者不會互相遮擋。
截圖處理

手機或網頁截圖直接疊上去會像誤觸的彈窗。先用 Python（PIL）加上白底、圓角、投影做成浮貼卡，再疊進畫面，才會像設計過的元素。放大倍率盡量不超過 2 倍，超過就該回頭找更高解析度的原圖。

06接片尾、統一響度、輸出

串接前規格不統一，是 concat 失敗或畫面錯亂的最常見原因。

串接

concat · 主片 ＋ 品牌片尾
# 前提：所有片段的解析度、幀率、SAR、取樣率、聲道數必須一致
printf "file 'cover.mp4'\nfile 'segA.mp4'\nfile 'outro.mp4'\n" > list.txt

ffmpeg -f concat -safe 0 -i list.txt \
  -c:v copy \
  -af "loudnorm=I=-14:TP=-1.5:LRA=11" -c:a aac -b:a 192k \
  -movflags +faststart final.mp4

三個收尾細節

做法參數為什麼
響度正規化loudnorm=I=-14−14 LUFS 是 YouTube 的標準值。太小聲觀眾直接滑走
結尾淡出fade=t=out:d=0.28畫面與音訊同時淡出，銜接品牌片尾才不突兀
快速起播-movflags +faststart把索引移到檔頭，上傳與預覽都更快
片尾素材要檢查最後一幀

許多片尾模板結尾是「滑出」動畫，最後 0.3 秒其實是空白畫面。直接接上去，影片會結束在一片黑。作法是裁到標題完全定位的時間點（本次 2.0 秒），再用 tpad=stop_mode=clone:stop_duration=0.5 凍結最後一幀，讓品牌卡停留住。

附錄 A常見坑速查

按出錯的頻率排序。前三項佔了實務上八成的除錯時間。

症狀原因修法
字幕跟不上嘴套用了 ASR 的區塊時間軸改用 silencedetect 的語句邊界，並用字數／秒驗收
關鍵字顏色不對ASS 色碼是 BGR 且含透明度#F5B800 → &H00B8F5&
字型變成預設宋體字型名稱與系統註冊名不符先跑 fc-list :lang=zh 照抄家族名
字幕超出畫面右側WrapStyle: 2 不會自動換行自己算每行字數上限，用 \N 手動斷行
輸出比預期長-t 放在 -i 之後裁切輸入要把 -t 放在 -i 之前
疊圖是半透明的抽的檢查幀剛好落在淡入淡出區間抽 fade 結束後的時間點再判斷

附錄 B學員練習

用自己的一支 30–60 秒素材完成，每一題都對應上面的一個階段。

➊ 語速檢驗（對應 STEP 2）

  1. 對自己的影片跑一次 silencedetect，把語句邊界抄成表格。
  2. 把逐字稿依語意分配到各語句，算出每一段的「字數 ÷ 秒數」。
  3. 找出偏離 4–6 字／秒的那一段，說明是分配錯了、還是 d 參數需要調整。

➋ 字卡改寫（對應 STEP 3）

  1. 挑出逐字稿中最長的三句，各改寫成不超過 14 字的下標題。
  2. 每張字卡標出一個關鍵字（只能一個），準備套用品牌色。
  3. 比對改寫前後的字數，計算刪掉了幾成。目標是 30% 以上。

➌ 樣式與燒錄（對應 STEP 4–5）

  1. 依「可用寬度 ÷ 字數」算出你的 Fontsize，寫出計算過程。
  2. 把你的品牌色從 HEX 換算成 ASS 的 BGR 格式。
  3. 燒錄後抽出三張畫面檢查：字幕是否超框、描邊是否足夠、是否落在 Shorts 遮擋區內。

本手冊的所有參數均取自實際專案：一支 45 秒的 Gemini Spark 教學短影音，22 張字卡、3 處畫面疊圖、1.4 倍變速、−14 LUFS 響度。數值請依自己的素材重新推導，不要直接照抄。
